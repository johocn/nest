## 3. 推荐：阶段5批3（技术债收尾 + 商业化闭环）

聚焦 2 个核心目标，每项独立可上线：

### 3-A 技术债：同类时区 bug 全量排查修复

冒烟暴露的时区问题并非支付独有，全库存在 3 处同类应用层时间比较：

| 位置 | 现状 | 影响 |
|---|---|---|
| `player.service.ts` isNewbie（~L215） | `Date.now() - player.createdAt.getTime()` | 新手保护期 daysLeft 差 8h 边界，轻微但不精确 |
| `activity.service.ts` 参与时长（~L470） | createdAt.getTime() 与 Date.now() 相减 | 活跃时长统计偏差 |
| `balance-audit.service.ts` 7/30 天窗口（~L73） | 应用层 `now - 7d` 与 DB UTC createdAt 比较 | 统计窗口偏移 8h，日边界统计错位 |

**修复原则**：与支付修复一致——时间窗口/时长判断统一改 SQL 端比较（`now()` 与列同源同基准），应用层不再用 `Date.now() - entity.createdAt.getTime()` 判断时长。

**验收**：grep 全库无新增 `createdAt.getTime()` 与 `Date.now()` 相减的时长判断（存量已清）；相关单测更新全绿；线上冒烟回归通过。

### 3-B 商业化闭环补齐

| 项 | 方案 | 验收 |
|---|---|---|
| VIP 专属拍卖室 | trade 拍卖链路接入 `vip.getPrivilegeValue`（如 exclusiveAuctionRoom 键），VIP 达标可开专属拍卖（白名单/独立列表） | 冒烟：非 VIP 开专属拍卖被拒；VIP 成功 |
| admin 补发社交积分 | 新增 admin 接口（原因走已预留的 `ADMIN`），支持给任意玩家加减分并记流水 | 冒烟：admin 补发 → 玩家 balance 变化、流水可查 |
| 真实微信支付接入 | **待用户决策**（需商户号/证书；建议维持 simulate 直到有真实商户诉求） | 决策后再立设计 |

**验收**：两接口冒烟全绿；全量单测回归通过；手册数据字典同步（如需新表/新接口）。
