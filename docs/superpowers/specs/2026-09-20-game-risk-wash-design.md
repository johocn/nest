# 互刷/洗分检测风控（离线批处理）设计

> 日期：2026-09-20
> 状态：已获批设计（brainstorming 产出）
> 定位：阶段6 商业化/盘子安全 — 经济/资产风控 第一打击目标「互刷/洗分检测」
> 处置姿态：**预警 + GM 手动处置**（达员不处罚，零误伤）

## 1. 背景与目标

社交游戏已有完整经济体系：trade 全家桶（negotiation/escrow/credit/bounty/barter/auction）、社会积分、帮会资金、礼物等跨账号价值流。这些价值流存在被多号互刷/洗分（资产在账号间对倒、单方向大额转移）绕过正常产出的风险。

本期做**互刷/洗分检测**：离线批处理扫描价值流，构建「账号→账号」转移关系，产出风险分与异常线索；GM 后台确认后手动冻结/回收。**只达员、不自动处罚**，风险最低。

## 2. 核心决策

| 维度 | 决策 |
|---|---|
| 引擎形态 | 离线批处理扫描（每 10 分钟定时任务），不侵入交易主链路 |
| 处置 | 预警 + GM 手动处置（冻结/回收/白名单） |
| 数据源 | trade 成交 + 礼物 + 帮会资金；道具对倒第一版列观察不纳入 |
| 风险分 | 0-100，账号评级 正常<40 / 关注40-70 / 高危≥70 |

## 3. 数据模型（新增 4 表）

- **`risk_wash_flow`**：归一化价值流，`{ id, from_id, to_id, asset_key, value, ts, biz_type, ref_id }`（ref_id 全局唯一，防重摄入）。biz_type ∈ trade_settle / negotiation / escrow / auction / barter / bounty / gift / guild_fund。
- **`risk_case`**：异常线索，`{ id, case_type, risk_score, status(open/frozen/white/ignored), reason_json, wf_ids[], created_at, handled_by, handled_at }`。case_type ∈ 回环对敲 / 失衡赠与 / 价值异动。
- **`risk_account_score`**：账号累计风险分，`{ player_id, risk_score, level, updated_at }`。
- **`risk_whitelist`**：误报豁免名单，`{ player_id, note, created_by, created_at }`。

配置走既有 `remote_configs` 的 `risk.*` 键（窗口、阈值、开关、豁免名单热加载）。

## 4. 检测信号与风险分

时间窗 `T`（默认 10 分钟内，批内聚合；可配）：

1. **回环对敲（60 分）**：`A↔B` 双向流量均达阈值，且净额近抵消（`|净差|/max(向流量) ≤ 20%`）但双向总量大 → 洗分嫌疑，覆盖「高买低卖」变体。
2. **失衡赠与（40 分）**：`A→B` 累计 ≥ 大额阈值 且 反向回流比例过低（顺/逆比低于阈值）→ 异常转移。
3. **价值异动（30 分）**：同资产短时对倒、价格偏离近期同资产成交基准（P50/P90）>2× 或频次暴涨。

账号累计分叠加封顶 100 → 评级。白名单账号跳过。

## 5. 调度与幂等

- 独立定时任务每 10 分钟跑一次：摄入新增流水 → 聚合窗口 → 判信号 → 产 risk_case / 更新 risk_account_score。
- 幂等：摄入按 `ref_id` 去重；重复执行不产生重复 case。
- 不引入新 npm 依赖，复用现有调度/Gateway 能力。

## 6. GM 处置接口（admin）

- 查异常线索列表 / 查账号风险分与明细
- **处置冻结**：一键回收涉案超额收益 + 记 audit 流水，可选联动 BAN（复用现有 admin 回收 + 封禁能力）
- 加白名单（误报豁免）

## 7. 验收

- 检测器单测：构造回环/失衡/异动样本，断言 case 生成与风险分正确
- 幂等测试：重复跑不重复产 case
- 配置热加载：remote_configs 阈值改动生效
- smoke：风控接口可达、处置流水留痕
- 无新 npm 依赖；2G 机禁 build，仅本地构建 + 推送；手册数据字典/接口索引同步

## 8. 风险点

- 批处理分钟级，非实时（接受）
- 误报 → 白名单豁免 + GM 处置把控
- 道具价值折算复杂度高，第一版不纳入检测谨防误报
